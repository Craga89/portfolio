AI assistants are starting to work inside the browser, on the page a person has open. Rather than leave them to read the screen and guess, I've given this site its own tools through WebMCP, a draft web standard. An agent calls a tool and gets structured answers, drawn from the same content visitors read. The same tools also run as an MCP server, so any MCP client can use them without the site open.

<InPractice>
- Each tool is defined once, in one shared module, and runs in both places: on the page through WebMCP and on the Worker through MCP. The site's search lives there too, so ask.sh, the page and the server can't drift apart.
- The tools read the same files the page loads, so an agent gets the same facts a visitor reads.
- The MCP server is public, read-only and rate-limited. It keeps no state between requests and serves both the current protocol (2026-07-28) and older clients.
- Browsers without WebMCP skip it. In Chrome it runs as an origin trial.
- CI tests both: the page's tools against a stand-in for the browser API, and the server against both protocol versions and the official MCP client. The ask tool is stubbed in tests, so they never reach the live service.
- For agents that read rather than act, the same content is in llms.txt and cv.json.
</InPractice>
