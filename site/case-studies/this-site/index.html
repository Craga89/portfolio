This site, run like a production system

It's a small site, but it's built and run the way I'd run a product. Everything lives in one public repository, every change goes through automated quality gates, and the AI feature has tests of its own. The results below come live from the latest CI runs.

Latest results

The latest Lighthouse, WCAG and ask.sh test results are live on the home page.

How a visit works
  • the pageBrowser→GitHub Pagesstatic, prerendered, works offline
  • ask.shBrowser→Cloudflare Workerrate-limited per visitor, and capped within the free daily AI allowance→Workers AIthree models, each a fallback for the one before; answers only from this site
  • countsBrowser→Cloudflare Worker→D1anonymous question log and visit counts
  • agentsAI agentin the browser→WebMCP or MCPthe same tools, on the page or on the Worker: profile, career, files, search and ask.sh
  • translationBrowserits built-in Translator API, when the visitor wants another language→on the device38 languages, right-to-left included; nothing is sent anywhere
What every change goes through
  1. buildprerender the page, self-host fonts, resize images, print cv.pdf, write the contact card and the ask.sh index
  2. deployGitHub Pages on every merge to main, stamped with the commit
  3. checkWCAG 2.2 AA suite, Lighthouse thresholds and a screenshot comparison against approved baselines
  4. workerunit tests, deploy, a smoke test, then the ask.sh answer tests
  5. weeklyevery check again, plus a dead-link check, visit and question stats, and the open-source counts
# in practice
  • The same gates I'd put on a product: a change that hurts accessibility, performance or the visuals fails its check.
  • The AI feature is tested like any other code, for the right facts, invented ones and prompt injection.
  • Anonymous counts instead of tracking: no cookies, no IP addresses, nothing that identifies a visitor.
  • It runs on the free tiers of GitHub Pages and Cloudflare.
